## 时间线

- 本仓库所有 `0.x` 版本共享同一时间线：**2033 年 11 月 13 日**（即设定中的“现在”）。
- 所有已记录事件均发生在该日期之前；`0.x` 不推进、不回退这个“现在”。
- 如需其他时间点（更早或更晚），请另开分支 `alt/<author>/<diverge>` 或 fork，并在文档中注明与主线的差异（规则见仓库根目录的 `README.md`）。
- `packaged_file.md` 末尾的时间戳是生成时间（现实时间），不是故事时间。
- 本约束只适用于故事内的“现在”，不适用于创作/提交时间（例如 `notes/` 与 `CHANGELOG.md` 中的现实日期）。

## 版本号规则

写法：`v<major>.<minor>.<patch>[-<stage>.<n>]`，例如 `v0.1.0`（正式）或 `v0.2.0-beta.1`（预览）。

| 位 | 含义 | 判据 |
|---|---|---|
| major | 锚点代际 | `0.x` 的锚点固定为 2033-11-13；`1.x` 起每推进一次锚点加 1。同一 major 内锚点不变 |
| minor | 设定内容 | 新增或改写设定事实（补白也算） |
| patch | 修订 | 勘误、措辞、格式，不改变事实 |

- `1.0.0` 的时点是 2033-11-13，beta 期在当天结束。
- `major = 0` 时，`meta.json` 的 `timeline` 必须为 `2033-11-13`；`major ≥ 1` 时必须晚于它。
- 历史版本 `v0.1-alpha.*`、`v0.1-beta.1/2` 保持原写法，不做追溯修改。

## 分支与 fork

### 分支命名

```
alt/<author>/<diverge>
```

- `<author>`：小写 ASCII，GitHub handle 优先；中文笔名写在分支根目录的 `ALT.md` 里。
- `<diverge>`：与主线历史开始不同的最早时间，格式 `YYYY-MM-DD`；说不清具体日期时分支名可用短 slug，但 `ALT.md` 中仍须填写日期。
- 同一作者的多条分支加后缀：`alt/<author>/2033-04-26-b`。
- 两三位作者选到同一时间线不算冲突——它们本来就是平行宇宙，可以并存。需要的是**可发现性**，不是仲裁：请在 `alt/INDEX.md` 登记。

### 分歧点在哪：开分支还是 fork

分歧点越早，主线失效的文件越多，按失效面积选择：

| 分歧点 | 处理 | 原因 |
|---|---|---|
| ≥ 2029-09-28（公司成立后） | 开 `alt/` 分支即可 | 只影响 `company.md`、`negotiation.md` 等局部 |
| 2028-06-01 ~ 2029-09-28（VTuber 出道后） | 开分支，但 `vtb.md` 必须重写 | 晴海・8103 的所属与形象线会变 |
| 2007-03-03 ~ 2028 | 建议 **fork**，不是分支 | 主角成长线大改，`profile`、`life_experience`、家人设定全部失效 |
| < 2007-03-03 | **必须 fork**，并视为另一个角色 | 已经不是李雪晴，不要挂在同一个名字下 |

一句话版本的规则：**同一角色、同一锚点 → 分支；不同角色或出生前改写 → fork 并改名。**

### 补白与分叉的区分

1. 与主线明文不冲突（只是把模糊处写具体）→ 这是**补白**，走 PR 回主线，不要开分支。
2. 冲突，但不改变已发生事件的结果（换视角、补动机、加旁支人物）→ 仍优先 PR；主线不收再考虑分支。
3. 冲突，且改变已发生事件的结果（谈判没谈成、她没有入职、父母没有南迁）→ 开 `alt/` 分支，并写 `ALT.md`。
4. 按上表阈值，早于 2029-09-28 的改写要评估失效面积，早于出生日的改写必须 fork。

### alt 分支必须提供 ALT.md

模板见 [`ALT.example.md`](ALT.example.md)。四个字段缺一不可，`text_packager.py` 会校验：

- 作者
- 锚点（与 `meta.json` 的 `timeline` 一致）
- 分歧点（`YYYY-MM-DD`，不得晚于锚点）
- 与主线差异（逐条列出，至少一条）

### 主线回收

`alt` 分支里如果有值得进主线的补白，走 PR 合并；`CHANGELOG.md` 中注明 `from alt/<author>`，以免作者开分支后再也回不到主线。

## 关于 packaged_file.md

- 该文件由 `text_packager.py` 生成，**请勿手工修改**；改完源文件后重新运行脚本，并把生成结果与源文件一起提交。
- 需要往打包结果里追加内容时，用 `meta.json` 的 `extend` 字段（支持追加文件、文件中的某一节或内联文本，详见 `README_TEXT_PACKAGER.md`），不要手改生成物。
- 时间线与分支规则由 `meta.json` 的 `policy` 字段启用（本仓库 `enforce_timeline: true`）；`text_packager.py` 本身是通用工具，不写 `policy` 的项目不受这些规则约束。
- 打包件用 `（xxx.md 开始）`／`（xxx.md 结束）` 标出每段内容的来源（由 `meta.json` 的 `source_markers` 控制）；`extend` 引入的小节显示为 `（README.md::时间线 开始）`。
- 工具版本与设定版本相互独立：工具版本见脚本顶部的 `TOOL_VERSION`、控制台输出与打包文件末尾；`meta.json` 的 `version_tag` 只表示设定版本。
- 脚本会校验时间线：`main` 上 `timeline` 必须为 `2033-11-13`；`alt/*` 上必须偏离该日期，且 `ALT.md` 四字段齐全。
- 打包标题会带上时间线；`alt` 分支还会带上分支名、作者与分歧点，避免读者混淆版本。
